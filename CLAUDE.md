# CLAUDE.md — pg.mccullo.ug architecture notes

This file is context for Claude (or any human) walking into the codebase cold. It's not a getting-started guide — it's a mental model of what's in here and why.

## Stack

- **React Router v7** (config-based routes in `app/routes.ts`) on Vercel Serverless via `@vercel/react-router`. Whole app compiles to a single serverless function.
- **MongoDB v6** (Atlas). All collections live in one database, `user_posts`.
- **AWS S3** for media, served through `/api/media/:filePath/*` with Sharp doing on-the-fly OG crops.
- **Fedify** for ActivityPub federation (Mastodon-compatible outbox + inbox).
- **@atproto/api** for Bluesky cross-posting (posts, videos, likes, replies).
- **OpenAI** `gpt-4o-mini` for alt-text + SEO meta + tags; `text-embedding-3-small` at 512 dims for related-posts similarity.
- **Web Push** via VAPID (self-hosted, no third-party push service).
- **Pusher** for real-time visitor notifications in the admin sidebar.
- **Sharp** for image resizing, OG title-card rendering (Pango backend with bundled Inter TTFs).
- **Vite + TypeScript strict mode**. Path alias `~/*` → `./app/*`.

## Route conventions

Routes are named to match the URL structure. `app/routes.ts` explicitly registers each one — nothing is auto-discovered. Three suffix conventions matter:

- `*.tsx` — has a UI component (default export). Loader runs server-side, component renders client-side.
- `*.ts` — resource route (loader/action only, no UI). Returns raw `Response`.
- `*.server.ts` — server-only helper module. React Router v7's Vite plugin strips imports of `.server.ts` files from the client bundle. **Anything touching `node:fs`, native bindings, or secrets should live in a `.server.ts` module.** A route file is not `.server` (it needs to be name-addressable in `routes.ts`), but it can and should delegate to `.server.ts` helpers.

`$name` in a filename = `:name` in the URL. Splat: `$.` for `*`.

Notable URL structure:

```
/                           → redirects to /h
/h                          → feed (also handles ?q=search)
/h/post/:id                 → post permalink
/h/post/:id/:slug           → same route, canonical slug'd version
/h/post/:id/analytics       → admin-only post analytics dashboard
/h/tag/:tag                 → tag archive page (h-feed)
/h/archive                  → year index
/h/archive/:year            → month index
/h/archive/:year/:month     → post list for that month
/h/about                    → author bio
/h/drafts                   → draft & scheduled post manager
/h/friends, /h/notifications, /h/visitor/:id  → admin surfaces
/h/*                        → rich 404 with recent posts + search

/api/*                      → resource routes (analytics, post CRUD, media, federation…)
/.well-known/webfinger      → Fedify WebFinger
/.well-known/nodeinfo       → Fedify NodeInfo discovery
/users/*                    → Fedify actor/inbox/outbox splat
/inbox                      → shared ActivityPub inbox

/api/micropub               → Micropub POST endpoint (IndieWeb clients)
/api/indieauth/{metadata,authorize,token}  → IndieAuth server
/api/webmention             → receive endpoint
/api/webmention/send        → deferred outgoing send

/sitemap.xml, /video-sitemap.xml, /feed.xml, /feed.json, /robots.txt
```

## Core data model (Mongo)

- **`myPosts`** — the posts collection. Fields worth knowing:
  - `content` (HTML), `created` (unix seconds), `lastEdited` (unix seconds)
  - `state`: `"draft" | "scheduled" | "published"` (missing = published, legacy compat)
  - `privacy`: `"Public" | "Followers" | "Friends" | "Self" | "Save Media" | "Story"`
  - `feedback`: `{ commentsOn, sharesOn, likesOn, likes[], shares[], comments[] }`
  - `media`: `{ audio, files, images[], links, videos[], imageAlts: { [filename]: text } }`
  - `tags: string[]` — normalized lowercase-hyphen (LLM-generated by default)
  - `seoMeta: { slug, description }` — LLM-generated, idempotent, never overwritten
  - `embedding: number[]` — 512-dim L2-normalized vector for related-posts similarity
  - `inReplyTo`, `blueskyUri`, `blueskyCid`, `scheduledFor`, `parentSnapshot` — situational
- **`myUsers`** — users. Role `"administrator"` = Patrick; everyone else is `"user"`. OAuth identities live under `external_ids.{provider}`.
- **`myVisitors`** — analytics. Each doc = one visitor identity with a `history[]` log of `{path, referrer, timestamp, ip, userAgent}` hops.
- **`federation_*`** — Fedify state: `federation_followers`, `federation_following`, `federation_inbox_posts`, `federation_my_reactions`, `federation_notifications`.
- **`webmentions`** — `{ source, target, targetPostId, verified, meta: {type, author, content, ...} }`. Composite key (source, target).
- **`myPushSubscriptions`** — Web Push endpoints for admin device notifications.
- **`micropub_tokens`** — IndieAuth access tokens for Micropub clients: `{ token, me, client_id, scope, created, lastUsed, revoked? }`.
- **`oauth_mastodon_apps`** — cached per-instance app registrations for Mastodon sign-in.

Serialization: ObjectIds and Dates don't round-trip through React Router's turbo-stream. Wrap loader returns with `serializeDoc()` / `serializeDocs()` from `~/utils/serialize.server`.

## Key patterns to preserve

### Idempotent LLM backfills

Any LLM-derived field (`seoMeta.slug`, `seoMeta.description`, `tags`, `media.imageAlts`, `embedding`) is **written once and never regenerated**. The generator endpoints check for the field's presence and no-op if it exists.

Rationale:
- Slugs become URLs — regenerating one silently breaks every existing share/backlink.
- Tags cluster posts — regenerating drifts categorization.
- Descriptions are meant to be "the summary of the post as-published" — an author's later edits shouldn't cascade into re-summarization unless requested.

The trigger pattern: any pageview of `/h/post/:id` inspects the post for missing derived fields; if any are missing, the loader fires a fire-and-forget `fetch()` to the deferred generation endpoint. First visitor pays the latency (invisibly); subsequent visitors see complete data.

### `publishSideEffects` fan-out

`app/utils/post-publish.server.ts` is the single source of truth for what happens when a public post is published:

1. **Federate to Mastodon followers** — awaited (needs to run inside the request budget so signed HTTP sigs actually happen).
2. **Fire deferred kickoffs** for LLM alt-gen, SEO meta, tag generation, embedding, webmention send. Each is an internal `fetch()` with `X-Internal-Token`, giving that job its own function budget.
3. **Cross-post to Bluesky** — inline for image-only (fast), deferred for video (encoding routinely blows the 10s Vercel budget).

Both `/api/post/create` (browser composer) and `/api/micropub` (IndieWeb clients) delegate to this helper. Any new publish surface should do the same — never duplicate the fan-out logic.

### Internal-only endpoints via `X-Internal-Token`

Endpoints that should never be user-facing (deferred workers) check for the `INTERNAL_API_TOKEN` env var in a header:

```typescript
const expected = process.env.INTERNAL_API_TOKEN;
if (!expected) return 500;
if (request.headers.get("x-internal-token") !== expected) return 401;
```

Same token also HMAC-signs IndieAuth authorization codes (short-lived stateless JWTs). Rotating the token invalidates in-flight codes but access tokens are Mongo-persisted so revocation is done via the collection.

### Federation model

- **Outbound**: `federatePostToFollowers` (create), `federatePostUpdate` (edit), `federatePostDelete` (privacy → private or actual delete). All in `~/utils/federation-posts.server`. Called from `publishSideEffects` and the update/delete endpoints.
- **Inbound**: Fedify handles the protocol at `/users/*` and `/inbox`. Actor + inbox activity dispatchers are configured in `~/utils/federation.server`. Received posts land in `federation_inbox_posts`; reactions land in `federation_my_reactions`; notifications in `federation_notifications`.
- **Bluesky**: separate `~/utils/bluesky.server` handles cross-post, reply, like. Bluesky reactions come back into the site via **Bridgy** (brid.gy/bluesky) → webmention endpoint.

### Media pipeline

- Upload: client presigns via `/api/upload/presign`, PUTs directly to S3.
- Serve: `/api/media/:filePath/*` proxies from S3, supports `Range` headers for video, `?og=1` for 1200×630 crop cached to S3 as `<name>_og.jpg`.
- Alt text: LLM-generated per image, stored under `post.media.imageAlts[filename]`. **Watch out for Mongo's dot-in-key handling** — filename `abc123.jpg` in a `$set` path becomes `{abc123: {jpg: ...}}` accidentally. Fix: write the whole `imageAlts` object at once (`$set: { "media.imageAlts": mergedMap }`).

### Micropub + IndieAuth

- Discovery: `<link rel="micropub|authorization_endpoint|token_endpoint|indieauth-metadata">` in `root.tsx`.
- Auth flow: client → `/api/indieauth/authorize` (admin session required + consent UI) → signed code → `/api/indieauth/token` (PKCE verify) → bearer token in `micropub_tokens`.
- Phase 1 (shipped): create endpoint (h-entry).
- Phase 2 (deferred): update / delete / `q=source`.
- Phase 3 (deferred): `/api/micropub/media` multipart uploads.

### Webmentions

- Receive: `/api/webmention` accepts POSTs, upserts to `webmentions` with (source, target) key, returns 202 immediately, fires background verifier.
- Verifier: fetches source URL, parses h-entry microformats via regex (no DOM lib), stores `meta: { type, author, content }`.
- Send: `/api/webmention/send` extracts up to 12 external links from a post's HTML, discovers each target's webmention endpoint, POSTs.
- Display: post loader fetches verified mentions, splits into reactions (like/repost/bookmark → facepile) and replies/mentions (quote cards).

### Sitemap + feeds

`/sitemap.xml` enumerates posts, tags, year/month archive pages. `/video-sitemap.xml` for video-bearing posts (Google video sitemap namespace). `/feed.xml` (Atom) and `/feed.json` (JSON Feed) for subscribers. Include slug URLs when `seoMeta.slug` exists.

## Common pitfalls

- **`fetcher.type` was removed in React Router v7.** Rewrite as `fetcher.state === "idle" && fetcher.data`.
- **Mongo dot-in-key**: filenames like `abc.jpg` in `$set` paths get interpreted as nested paths. Write whole objects instead of dotted subpaths when keys can contain dots.
- **ObjectId + Date don't turbo-stream through loader → client.** Use `serializeDoc()` / `serializeDocs()`.
- **`node:fs` in route files breaks Vite/Rollup client-bundling.** Move fs-touching code into `.server.ts` helpers.
- **Vercel Hobby has a 10s function budget.** Long-running ops (Bluesky video encoding, big LLM calls) must be deferred to their own function via an internal fetch.
- **DNS negative-cache TTLs are long.** New A records can take 15+ min to propagate through Google's public resolver.
- **Windows Git Bash uses `rm`, not `del`.** Stale `.git/index.lock` → `rm .git/index.lock`.
- **`git push` from the sandbox is blocked.** All commits happen locally and get pushed from Patrick's machine.

## Testing / verification

There's no test suite. Verification pattern for changes:

- Syntax: `node -e "require('typescript').createSourceFile(...)"` for parse-only check on modified files (faster than full `tsc`).
- Semantics: `node --experimental-strip-types --check <file>` on `.ts` (not `.tsx`).
- End-to-end: Vercel preview deploy + tail logs (`vercel logs --follow`). Prefix log lines with feature tags (`[federation]`, `[bluesky]`, `[embedding]`, `[seo-meta]`, `[webmention]`, `[alt-gen]`) so `grep` narrows quickly.

Full `tsc --noEmit` in the sandbox often times out; run locally before committing anything complex.
